## Notes

- A zero-finding review with no quoted evidence is weak assurance. Both Gemini replies had no quoted lines. I rely on the checks above, not on the reviews.
- Review 1 missed a real gap. In `load_model`, `estimator.get_params()` was outside the `try`, so a file that loads but holds the wrong object raised `AttributeError` instead of `ModelUnavailable`. I confirmed this by loading such a file. On main that is an unhandled 500 on the first prediction. With the startup hook it would have stopped the app from starting, which contradicts what this PR says. The assistant found it while reading `load_model` to write this log. It is fixed in d8a9589 with a unit test and a startup test.
- The gap was already on main before this PR. No earlier review and no CI run caught it.
- The startup hook reads settings directly instead of through the FastAPI dependency, so the tests point it at their files with environment variables. The dependency override alone would not reach it.
- Startup now waits for the model load, so the container takes longer to become ready. That is the cost of a fast first request.
- The change was written with Claude. The triage above was also done with Claude, so it is not independent. The reviews themselves came from Gemini, a different vendor.
