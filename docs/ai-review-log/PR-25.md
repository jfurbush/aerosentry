## Notes

- A summary with no finding and no quoted line is weak assurance. The assistant also read the diff for risks the reply did not mention. The one it found is the limit in the next point.
- Limit: `readings` is created by pandas `to_sql` with no NOT NULL constraints. If a sensor value were ever NULL, the engine page would fail with an unhandled error, because the chart code converts each value to a number. The real FD001 data has no NULLs, so this cannot happen with the project's data, and I have not added handling for it.
- The sensor names and units were transcribed by the assistant from a web fetch of Table 2 in Saxena et al. (PHM 2008). The assistant could not open the paper directly. The unit test compares them with a second copy from the same fetch, so it catches accidental edits and would not catch a wrong transcription. A person has not yet compared the 21 rows with the paper at the time of this log.
- The error responses of `/` and `/engines/{id}` changed from JSON to HTML. The status codes did not change, and the JSON API paths still answer in JSON. Tests cover both.
