| 1 | Medium. `app/main.py`: an engine that is listed but has no rows in `features` gets the 404 "Engine not found" page, which blurs "unknown engine" and "data problem". | 2 | Medium, raised as a question. Do `latest_features` (`ORDER BY cycle DESC LIMIT 1`) and `feature_history(...)[-1]` pick the same row if cycles are duplicated? Suggests the route use `latest_features` for the current value. | Rejected | The question rests on duplicate cycles, which cannot exist. `pipeline/load_db.py` line 70 creates `CREATE UNIQUE INDEX idx_features_key ON features (engine_id, cycle)`. I tried inserting a second row for engine 1 at its last cycle into a copy of the real database and SQLite refused it (`UNIQUE constraint failed: features.engine_id, features.cycle`). With unique cycles both queries return the row with the highest cycle. The route calling `feature_history` once and using its last element also avoids a second query. The equality of page and `/predict` is tested for engines 1 to 3 by `test_the_last_chart_point_is_the_rul_the_api_returns`. I had told myself earlier that these tables have no constraints. That was wrong for the key columns; the columns themselves can still hold NULL. |
| 3 | Medium. `test_series_matches_one_prediction_per_row` compares the batch function with the single-row function, and the single-row function now calls the batch function, so it checks the code against itself. Suggests comparing with `model.estimator.predict` directly. | Accepted in part | The reviewer's example is wrong. I patched `predict_rul_series` to repeat its first prediction for every row. The existing test then fails, because the single-row call still returns the correct first value for each row. The point still holds for a bug shared by both paths, such as wrong column order or a wrong clamp. I added `test_series_matches_the_estimator_called_directly` in commit bb60adf. It builds the frame in `model.feature_columns` order, calls `model.estimator.predict`, applies `min(max(raw, 0), rul_clip)` and rounds to 1 decimal itself, then compares with the series for engine 1 of the fixture. I also ran the same oracle on the real model and real engine 1 and it matched the series exactly. I did not mutation-test the new test beyond that. |
